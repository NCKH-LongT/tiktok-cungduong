# TikTok Cúng Dường AI Live

Monorepo for a multi-LIVE dashboard, event pipeline and OBS temple overlay. The current implementation contains a usable simulator and initial live connector; read [progress](docs/PROGRESS.md) before production use.

## Local setup

Requirements: Node 22, npm 10, Docker Compose.

1. Copy `.env.example` to `.env` and set strong `POSTGRES_PASSWORD`, `ADMIN_EMAIL` and `ADMIN_PASSWORD` (16+ characters). Keep `.env` out of Git. Existing `.env.gitignore` can be used as a private source of credentials but is ignored by Git.
2. Run `npm ci`, then `npm run build`.
3. Run `docker compose --env-file .env up -d --build --wait`.
4. Open `http://localhost:8090` and sign in with the bootstrap admin.
5. Create a LIVE channel, rotate an overlay token, open the OBS URL, and use the Simulator tab to test events.

The default `TIKTOK_CONNECTOR_MODE=simulator` never contacts TikTok. Set it to `tiktok`, rebuild/recreate Compose, then click **Kết nối TikTok** for a channel that is currently LIVE. Enter the username with or without `@`; it is stored without `@`. The `thaobedim` channel connected on 2026-10-31 without a signing key. If TikTok works on the host but the worker stays `connecting`, check `docker compose logs tiktok-worker`; the worker uses `TIKTOK_DNS` (default `1.1.1.1`) because this host's Docker DNS could not resolve TikTok. AI comment answers require `GEMINI_API_KEY`. Google TTS requires a service-account JSON in `./secrets` and `GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/<filename>.json` in the Compose environment. Voice ID, speaking rate and pitch are configured per LIVE in Voice & Audio; the available Vietnamese voice IDs come from [Google's voice list](https://docs.cloud.google.com/text-to-speech/docs/list-voices-and-types). Without Google credentials, the overlay uses the browser's Vietnamese speech synthesis when available; voice quality depends on the browser. The Simulator tab can explicitly test AI without counting the event as real LIVE activity.

## Thanh toán payOS

Các tài khoản `ADMIN` và `SUPER_ADMIN` dùng miễn phí. Tài khoản khác phải thanh toán 50.000₫ để dùng LIVE trong 24 giờ; mua thêm sẽ nối tiếp thời hạn còn lại. Đăng nhập vẫn mở để người hết hạn có thể nạp tiền. Quyền dùng LIVE chỉ được cấp sau khi máy chủ xác minh webhook payOS hoặc đối chiếu trạng thái đơn trực tiếp với payOS; tham số trên URL quay lại không cấp quyền. Lời chào AI chỉ phát một lần cho mỗi người trong cùng phòng LIVE, kể cả khi người đó ra rồi vào lại. AI bỏ qua bình luận có dưới hai từ.

Đặt `PAYOS_CLIENT_ID`, `PAYOS_API_KEY`, `PAYOS_CHECKSUM_KEY` vào `.env` riêng tư và cập nhật lại **Secret file** credential `tiktok-cungduong` trên Jenkins nếu file đã tải lên trước khi thêm các khóa này. Trong bảng điều khiển payOS, đăng ký webhook `https://<PUBLIC_APP_URL-domain>/api/billing/payos/webhook` (thay bằng domain HTTPS thật). Cấu hình `PUBLIC_APP_URL` cùng domain HTTPS để payOS trả khách về dashboard. Kiểm tra webhook bằng môi trường thử nghiệm payOS trước khi nhận thanh toán thật. Không đưa khóa payOS vào Git.

The OBS scene loads the supplied `apps/web/public/overlay/chanhdien.png` and the standing, kneeling and bowing frames from `apps/web/public/overlay/nhanvat01.png`. Each viewer gets a `BuddhistUserBadge` built from the supplied `bang-ten-phat-tu.png`: TikTok avatar and Unicode nickname remain separate HTML layers, so the PNG is never regenerated when a name changes. The badge follows and scales with its character. A new viewer enters from the bottom, walks to a free place, kneels, bows once, then remains kneeling until leaving or inactivity timeout.

The LIVE dashboard shows current room viewers and total viewers from TikTok `ROOM_USER`, unique join IDs, comments, gift totals, like events, heart counts and shares for the latest broadcast room. It combines successful worker sessions with the same TikTok room ID, and lists recent comments and gifts. Older records created before room IDs were stored fall back to their last successful worker session. TikTok does not send a reliable per-viewer leave event in this connector; the overlay removes the least recently active characters when the reported room count drops, or when their inactivity timeout expires. Resting characters bow occasionally for ambient motion; reduced-motion mode disables those extra bows. The Simulator can emit a room count to test inferred departures. The worker retries an unavailable LIVE with backoff and reconnects if its stream becomes stale.

YouTube music uses the official IFrame Player API, but its 1×1 player is placed offscreen so the video cannot cover the scene. Autoplay can be blocked; the overlay then shows a **Bật nhạc YouTube** button. Gift events zoom into the giver and blur/dim other characters; reloading the overlay restores presence without replaying old gifts or zooms. AI replies appear in the **AI Assistant** history and in the overlay for at least six seconds. Google TTS audio uses the selected Vietnamese voice when a credential file is available; if synthesis fails, the text still reaches the overlay for browser speech. If the browser blocks speech, use **Bật giọng đọc tiếng Việt**. OBS Browser Source must capture overlay audio. Use music you have permission to play.

## VPS and CI/CD

On Ubuntu, install Docker Engine and the Compose plugin, configure DNS, and place a private `.env` on the server. Mount an Nginx TLS configuration and Let's Encrypt certificates using `infrastructure/nginx/https.conf.example` as the template. Change `PUBLIC_APP_URL` and `PUBLIC_OVERLAY_URL` to the HTTPS domain. The Compose default listens on HTTP port 8090 for local verification.

Configure a Jenkins **Pipeline** job with **Pipeline script from SCM**: Git repository `https://github.com/NCKH-LongT/tiktok-cungduong.git`, Git credential `github-cungduong` (for a private repository), branch specifier `*/main`, script path `Jenkinsfile`, and lightweight checkout enabled. Enable **GitHub hook trigger for GITScm polling** and add a push webhook at `https://<your-jenkins-host>/github-webhook/`. The Jenkinsfile also verifies that the checked-out commit matches `origin/main` before installing or building. Run the job on a persistent Docker-capable agent on the target host. On every successful main build, Jenkins deploys automatically using a **Secret file** credential with ID `tiktok-cungduong` containing the production `.env`. Deployment pins host HTTP port 8090 even if that file still contains `HTTP_PORT=8080`; update public URLs in the credential when they include an explicit local port. Keep secret JSON files in `./secrets` on that host.

The Docker build keeps one cache archive, `.docker-build-cache.tar`, in the Jenkins workspace. Do not clean that file between builds. CI images are tagged `tiktok-cungduong-app:<build number>`; after each successful build, Jenkins keeps at most three numbered CI tags and removes legacy `tiktok-cungduong:<build number>` tags before deployment. A still-running older image is protected until a later build. Deploy reuses the verified image without another build. If the Jenkins agent lacks Node 22/npm, CI downloads a checksum-verified Node 22 runtime into the ignored `.ci-tools/` workspace directory; this requires outbound access to `nodejs.org`, `curl`, `tar`, and `sha256sum`. On failure, the Jenkins console shows the failing command and exit code, and the job archives `ci-logs/*.log` with Docker container diagnostics. Docker CLI, Compose and Buildx plugins, `bash`, and Docker daemon access are required on the agent. If Jenkins runs in a container against the host Docker daemon, its workspace path and `./secrets` must also exist at the same paths on the Docker host for Compose bind mounts; running a Docker-capable agent directly on the deployment host avoids that path mismatch. The Jenkinsfile retains the latest 20 Jenkins build records.

PostgreSQL and Redis use named volumes. Back up with `docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup.sql` from a shell where those variables are set; encrypt and store backups outside the host. Test restore into a separate database. Do not copy database or Redis ports to public interfaces.

## Developer commands

`npm run db:generate` generates Prisma client. `npm run db:migrate` applies checked-in migrations. `npm run db:bootstrap` creates the admin from environment variables. `npm test` runs unit tests. `npm run typecheck` verifies TypeScript. `npm run test:smoke` exercises the running stack from login through simulator and token revoke; set `SMOKE_BASE_URL`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` in the shell. `npm run test:stats-smoke` checks session-scoped analytics against a temporary database fixture. With a configured Gemini worker, `npm run test:ai-smoke` checks the simulator → Gemini → speech socket path. See [architecture](docs/ARCHITECTURE.md) and [plan](docs/IMPLEMENTATION_PLAN.md).
