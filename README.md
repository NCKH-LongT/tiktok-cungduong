# TikTok Cúng Dường AI Live

Monorepo for a multi-LIVE dashboard, event pipeline and OBS temple overlay. The current implementation contains a usable simulator and initial live connector; read [progress](docs/PROGRESS.md) before production use.

## Local setup

Requirements: Node 22, npm 10, Docker Compose.

1. Copy `.env.example` to `.env` and set strong `POSTGRES_PASSWORD`, `ADMIN_EMAIL` and `ADMIN_PASSWORD` (16+ characters). Keep `.env` out of Git. Existing `.env.gitignore` can be used as a private source of credentials but is ignored by Git.
2. Run `npm ci`, then `npm run build`.
3. Run `docker compose --env-file .env up -d --build --wait`.
4. Open `http://localhost:8090` and sign in with the bootstrap admin.
5. Create a LIVE channel, rotate an overlay token, open the OBS URL, and use the Simulator tab to test events.

The default `TIKTOK_CONNECTOR_MODE=simulator` never contacts TikTok. Set it to `tiktok`, rebuild/recreate Compose, then click **Kết nối TikTok** for a channel that is currently LIVE. Enter the username with or without `@`; it is stored without `@`. The `thaobedim` channel connected on 2026-10-31 without a signing key. If TikTok works on the host but the worker stays `connecting`, check `docker compose logs tiktok-worker`; the worker uses `TIKTOK_DNS` (default `1.1.1.1`) because this host's Docker DNS could not resolve TikTok. AI comment answers require `GEMINI_API_KEY`. Google TTS requires a service-account JSON in `./secrets` and `GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/<filename>.json` in the Compose environment. Voice ID, speaking rate and pitch are configured per LIVE in Voice & Audio; the available Vietnamese voice IDs come from [Google's voice list](https://docs.cloud.google.com/text-to-speech/docs/list-voices-and-types). If Google TTS is unavailable or reaches its quota, the CPU-only KorvaTTS service creates an MP3 locally and sends it to the overlay. The model downloads to the `tts-models` Docker volume on first startup and can take a few minutes to become ready. `LOCAL_TTS_VOICE` defaults to `khanh_vy`; `LOCAL_TTS_THREADS` defaults to `2`. If both TTS services fail, browser speech synthesis is the final fallback. Check `docker compose logs local-tts ai-worker` and the AI activity status when audio is missing. The Simulator tab can explicitly test AI without counting the event as real LIVE activity.

## Xóa LIVE và cấu hình AI riêng

Trong danh sách LIVE, nút **Xóa TikTok ID và dữ liệu** dừng kết nối, hủy các tác vụ AI đang chờ và xóa vĩnh viễn bản ghi LIVE cùng bình luận, quà, người xem, lịch sử AI, token overlay và cấu hình liên quan. Tài khoản hết hạn gói vẫn xem được danh sách và xóa dữ liệu của mình. MP3 do Google TTS tạo chỉ tồn tại trong bộ nhớ để gửi qua WebSocket; ứng dụng không lưu file ghi âm trên ổ đĩa. Overlay chỉ giữ một âm thanh đang chờ và giải phóng buffer sau khi phát.

Mỗi LIVE có thể lưu Gemini API key riêng tại tab **AI Assistant**. Key được mã hóa AES-256-GCM và không được trả lại qua API. Đặt `ENCRYPTION_KEY` ngẫu nhiên dài ít nhất 32 byte trong `.env` và cập nhật cùng giá trị trong Jenkins Secret file `tiktok-cungduong`; giữ key này ổn định để đọc được các khóa đã lưu. Nếu bỏ key riêng, ứng dụng dùng `GEMINI_API_KEY` của máy chủ. Không đưa các khóa vào Git.

Google TTS có giới hạn 30 request/phút toàn hệ thống theo mặc định (`TTS_RPM_LIMIT`) và tối đa 100 lượt/ngày cho mỗi tài khoản theo `UserQuota.maxTtsPerDay`; tab AI hiển thị số lượt còn lại và nguồn âm thanh của từng câu trả lời. Nếu Google TTS lỗi hoặc hết lượt, [KorvaTTS](https://github.com/dogenthq/KorvaTTS) chạy trên CPU sẽ tạo MP3 tiếng Việt ngay trên máy chủ. Gemini vẫn tạo nội dung; KorvaTTS chỉ tạo giọng đọc. Model dùng giấy phép Apache-2.0 và tải một lần vào Docker volume `tts-models`. Nếu cả hai nguồn đều lỗi, overlay mới thử giọng trình duyệt. `GEMINI_RPM_LIMIT` mặc định là 5 request/phút. [Cloud TTS quotas](https://docs.cloud.google.com/text-to-speech/quotas) và [Gemini rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) của tài khoản Google vẫn áp dụng riêng.

Trang **Quản trị tài khoản** cho phép admin đặt Google hoặc local làm nguồn giọng đọc ưu tiên cho từng tài khoản. Mọi LIVE của tài khoản dùng nguồn đó; nếu nguồn ưu tiên không tạo được MP3, worker thử nguồn còn lại. Cấu hình mới áp dụng cho câu trả lời kế tiếp, không cần khởi động lại container. Các URL trong `PUBLIC_APP_URL` và `CORS_ORIGINS` được chuẩn hóa về origin để `http://localhost:8090/` vẫn khớp với Origin do trình duyệt gửi.

Để thử đăng nhập local khi khóa Turnstile production không cho phép `localhost`, đặt `LOCAL_TURNSTILE_TEST=true` trong `.env` local rồi chạy lại Compose. Chế độ này dùng [bộ khóa thử nghiệm chính thức của Cloudflare](https://developers.cloudflare.com/turnstile/troubleshooting/testing/) và chỉ hoạt động khi `PUBLIC_APP_URL` có hostname `localhost` hoặc `127.0.0.1`; khóa production trong `.env` không bị thay đổi.

## Thanh toán payOS

Các tài khoản `ADMIN` và `SUPER_ADMIN` dùng miễn phí. Tài khoản khác phải thanh toán 50.000₫ để dùng LIVE trong 24 giờ; mua thêm sẽ nối tiếp thời hạn còn lại. Đăng nhập vẫn mở để người hết hạn có thể nạp tiền. Quyền dùng LIVE chỉ được cấp sau khi máy chủ xác minh webhook payOS hoặc đối chiếu trạng thái đơn trực tiếp với payOS; tham số trên URL quay lại không cấp quyền. Lời chào AI chỉ phát một lần cho mỗi người trong cùng phòng LIVE, kể cả khi người đó ra rồi vào lại. AI bỏ qua bình luận có dưới hai từ.

Đặt `PAYOS_CLIENT_ID`, `PAYOS_API_KEY`, `PAYOS_CHECKSUM_KEY` vào `.env` riêng tư và cập nhật lại **Secret file** credential `tiktok-cungduong` trên Jenkins nếu file đã tải lên trước khi thêm các khóa này. Trong bảng điều khiển payOS, đăng ký webhook `https://<PUBLIC_APP_URL-domain>/api/billing/payos/webhook` (thay bằng domain HTTPS thật). Cấu hình `PUBLIC_APP_URL` cùng domain HTTPS để payOS trả khách về dashboard. Kiểm tra webhook bằng môi trường thử nghiệm payOS trước khi nhận thanh toán thật. Không đưa khóa payOS vào Git.

Đăng nhập Turnstile dùng `TURNSTILE_SITE_KEY` và `TURNSTILE_SECRET_KEY` của cùng một widget trong Jenkins Secret file. Thêm `farm-cong-duc.nongdanonline.cc` vào danh sách hostname được phép của widget. Token chỉ dùng một lần; giao diện tự tạo token mới sau khi đăng nhập thất bại hoặc token hết hạn. Nếu xác minh vẫn lỗi, xem mã lỗi Turnstile trong log container API; log không chứa secret hay token.

The OBS scene loads the supplied `apps/web/public/overlay/chanhdien.png` and the standing, kneeling and bowing frames from `apps/web/public/overlay/nhanvat01.png`. Each viewer gets a `BuddhistUserBadge` built from the supplied `bang-ten-phat-tu.png`: TikTok avatar and Unicode nickname remain separate HTML layers, so the PNG is never regenerated when a name changes. The badge follows and scales with its character. A new viewer enters from the bottom, walks to a free place, kneels, bows once, then remains kneeling until leaving or inactivity timeout.

The LIVE dashboard shows current room viewers and total viewers from TikTok `ROOM_USER`, unique join IDs, comments, gift totals, like events, heart counts and shares for the latest broadcast room. It combines successful worker sessions with the same TikTok room ID, and lists recent comments and gifts. Older records created before room IDs were stored fall back to their last successful worker session. TikTok does not send a reliable per-viewer leave event in this connector; the overlay removes the least recently active characters when the reported room count drops, or when their inactivity timeout expires. Resting characters bow occasionally for ambient motion; reduced-motion mode disables those extra bows. The Simulator can emit a room count to test inferred departures. The worker retries an unavailable LIVE with backoff and reconnects if its stream becomes stale.

YouTube music uses the official IFrame Player API, but its 1×1 player is placed offscreen so the video cannot cover the scene. Autoplay can be blocked; the overlay then shows a **Bật nhạc YouTube** button. Gift events zoom into the giver and blur/dim other characters; reloading the overlay restores presence without replaying old gifts or zooms. AI replies appear in the **AI Assistant** history and in the overlay for at least six seconds. Google TTS audio uses the selected Vietnamese voice when a credential file is available; KorvaTTS supplies MP3 if Google fails or reaches its quota. If the browser blocks audio playback, use **Bật giọng đọc tiếng Việt**. OBS Browser Source must capture overlay audio. Use music you have permission to play.

## VPS and CI/CD

On Ubuntu, install Docker Engine and the Compose plugin and configure DNS. Set `PUBLIC_APP_URL` and `PUBLIC_OVERLAY_URL` to the public HTTPS domain in the Jenkins Secret file. The Compose stack publishes HTTP port 8091. Point the separate TLS reverse proxy to port 8091 and forward WebSocket upgrade headers for `/socket.io/`. The Nginx container inside Compose only routes requests to the web and API containers; its configuration is generated at startup and needs no host file mount.

Configure a Jenkins **Pipeline** job with **Pipeline script from SCM**: Git repository `https://github.com/NCKH-LongT/tiktok-cungduong.git`, the existing Git credential `ftacode-github` (for this private repository), branch specifier `*/main`, script path `Jenkinsfile`, and lightweight checkout enabled. Add a push webhook at `https://jenkins.lexatek.vn/github-webhook/`. The Jenkinsfile declares `githubPush()` so the GitHub plugin registers the job for push events. After changing this trigger, run **Build Now once** to load the new Jenkinsfile; later pushes to `main` start builds automatically. The Jenkinsfile also verifies that the checked-out commit matches `origin/main` before installing or building. Run the job on a persistent Docker-capable agent on the target host. On every successful main build, Jenkins deploys automatically using a **Secret file** credential with ID `tiktok-cungduong` containing the production `.env`. Deployment pins host HTTP port 8091 and sets `PUBLIC_APP_URL` and `PUBLIC_OVERLAY_URL` to `https://farm-cong-duc.nongdanonline.cc` even if the Secret file still has localhost values; `DEPLOY_PUBLIC_APP_URL` and `DEPLOY_PUBLIC_OVERLAY_URL` can override those deployment defaults later. The local `.env` may keep localhost for development. Keep any Google TTS credential JSON in `./secrets` on the Docker host, mounted from the same path visible to the Docker daemon.

The Docker build keeps one cache archive, `.docker-build-cache.tar`, in the Jenkins workspace. Do not clean that file between builds. CI images are tagged `tiktok-cungduong-app:<build number>`; after each successful build, Jenkins keeps at most three numbered CI tags and removes legacy `tiktok-cungduong:<build number>` tags before deployment. A still-running older image is protected until a later build. Deploy reuses the verified image without another build. If the Jenkins agent lacks Node 22/npm, CI downloads a checksum-verified Node 22 runtime into the ignored `.ci-tools/` workspace directory; this requires outbound access to `nodejs.org`, `curl`, `tar`, and `sha256sum`. On failure, the Jenkins console shows the failing command and exit code, and the job archives `ci-logs/*.log` with Docker container diagnostics. Docker CLI, Compose and Buildx plugins, `bash`, and Docker daemon access are required on the agent. The Jenkinsfile retains the latest 20 Jenkins build records.

PostgreSQL and Redis use named volumes. Back up with `docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup.sql` from a shell where those variables are set; encrypt and store backups outside the host. Test restore into a separate database. Do not copy database or Redis ports to public interfaces.

## Developer commands

`npm run db:generate` generates Prisma client. `npm run db:migrate` applies checked-in migrations. `npm run db:bootstrap` creates the admin from environment variables. `npm test` runs unit tests. `npm run typecheck` verifies TypeScript. `npm run test:smoke` exercises the running stack from login through simulator and token revoke; set `SMOKE_BASE_URL`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` in the shell. `npm run test:stats-smoke` checks session-scoped analytics against a temporary database fixture. With a configured Gemini worker, `npm run test:ai-smoke` checks the simulator → Gemini → speech socket path. See [architecture](docs/ARCHITECTURE.md) and [plan](docs/IMPLEMENTATION_PLAN.md).
